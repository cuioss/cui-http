== Findings
=== F-D-14: Benchmark `+assemble+` step tolerates a missing results directory and the deploy step then wipes the published benchmark site
* Severity: Medium
* Category: correctness (CI/operational)
* Status: CONFIRMED (traced)
* Location: cui-http-benchmarking/scripts/benchmark-pages.py:172-177 (`+print(f"Warning: … skipping")+`, no exit), :201-223 (still writes `+badges/+` and `+metadata.json+`); .github/workflows/benchmark.yml:112-122 (`+rm -rf "$TARGET_DIR"; cp -r gh-pages/*; git commit+`), :65-73 (`+Fetch Previous History … continue-on-error: true+`).
* Analysis: If `+target/benchmark-results/gh-pages-ready+` is absent (layout change in benchmarking-common, partial run) the script exits 0 with a near-empty `+gh-pages/+`; the deploy step deletes `+cui-http/benchmarks+` on cuioss.github.io and commits the empty tree — the whole history and index are lost. Likewise a transient failure of the "Fetch Previous History" checkout (`+continue-on-error: true+`) silently discards all previously deployed history in the same push. The step "Run Micro Benchmarks" only lists `+target/benchmark-results/+`, not the `+gh-pages-ready+` sub-directory the script needs.
* Recommendation: In `+assemble+`, `+sys.exit(1)+` when `+present_modules+` is empty; in the workflow, fail if `+gh-pages-ready/index.html+` is missing, and make the history fetch mandatory (or skip the deploy when it failed) instead of `+continue-on-error+`.

=== F-D-15: Generators classifier jar leaks a nested test class and carries a duplicate module name
* Severity: Low
* Category: consistency (build)
* Status: CONFIRMED
* Location: cui-http-core/pom.xml:91-98 (the classifier execution; the single `+<exclude>…/**/*Test.class</exclude>+` is at :98 — line numbers corrected after adversarial verification); target/test-classes/de/cuioss/http/security/generators/SupportedValidationTypeGeneratorContractTest$1.class exists; cui-java-parent-1.6.2.pom:76-78 applies `+Automatic-Module-Name: ${maven.jar.plugin.automatic.module.name}+` (= `+de.cuioss.http+`, core pom line 66) to every jar-plugin execution.
* Analysis: The classifier artifact IS produced (CLAUDE.md claim verified) and guarded by the enforcer rule, but (a) nested classes of excluded tests (`+*Test$*.class+`) ship inside it; (b) the classifier jar's manifest declares automatic module `+de.cuioss.http+`, the same name as the main jar's `+module-info+` — putting both on the module path fails with a duplicate module. Tests run on the classpath so this is latent; the doc (test-generators-readme.adoc:22-24) does not mention it.
* Recommendation: Add `+<exclude>…/**/*Test$*.class</exclude>+` (and the same two excludes for the `+database+` package), and either set a distinct `+Automatic-Module-Name+` for the classifier execution or document "classpath only".

=== F-D-17: Benchmark data/naming issues (measurement validity)
* Severity: Info
* Category: consistency
* Status: CONFIRMED (code)
* Location: ValidationStageBenchmark.java:45-48 (`+decodingStage+` fed `+nextCleanUrl()+` — none of `+SecurityBenchmarkState.CLEAN_URLS+`, :56-67, contains `+%+`), :57-60 (`+normalizationStage+` fed URLs without dot-segments); PipelineThroughputBenchmark.java:41-49 (`+measureThroughput+` and `+urlPathCleanThroughput+` are byte-identical); PipelineLatencyBenchmark.java:36 / ValidationStageBenchmark.java:36 (`+@Threads(1)+` is overridden by the global `+jmh.threads+`, per the pom comment at cui-http-benchmarking/pom.xml:45-50).
* Analysis: The stage-isolation benchmarks measure the fast no-op path of the decoding and normalization stages, so their Javadoc ("URL percent-encoding and UTF-8 overlong detection", "RFC 3986 path normalization with traversal detection") overstates what is measured. Dead-code elimination is correctly prevented everywhere (all `+@Benchmark+` methods return the result). `+SecurityBenchmarkState.CLEAN_PARAMS+` are name-shaped tokens (`+page1size20+`) fed to the parameter-*value* pipeline — realistic enough, but not query values as an application would see them.
* Recommendation: Feed the decoding/normalization stage benchmarks inputs that actually exercise them (e.g. `+/api/%2e%2e/x+`, `+/a/./b/../c+`); drop one of the duplicate throughput methods or make `+measureThroughput+` a mixed workload as its Javadoc claims.

=== F-D-18: benchmark.yml — GitHub App token requested for this repository although only cuioss.github.io is written
* Severity: Low
* Category: security-gap (least privilege)
* Status: CONFIRMED
* Location: .github/workflows/benchmark.yml:39-46 (`+repositories: ${{ github.event.repository.name }},cuioss.github.io+`), :104-141 (token used only for the pages checkout/push)
* Recommendation: `+repositories: cuioss.github.io+`. (Everything else checked: all `+uses:+` pinned by full SHA with version comments, `+permissions: contents: read+` at workflow and job level, `+persist-credentials: false+` on the source checkout, `+github.sha+` is the only expression interpolated into `+run:+` scripts.)


== Verified strengths
* JPMS: all 13 source packages are exported; `+requires transitive java.net.http+` (HttpHandler/converters expose `+java.net.http+` types), `+org.jspecify+` and `+de.cuioss.java.tools+` (LogRecord in public API) are justified; `+requires static lombok+` correct; no reflection → no `+opens+` needed; `+javax.net.ssl+` is in `+java.base+`. Surefire `+useModulePath=false+` is inherited from the root pom as CLAUDE.md states.
* POM versions are consistent: root/core/benchmark `+3.1-SNAPSHOT+`, project.yml `+next-version: 3.1-SNAPSHOT+`, `+okhttp-tls 5.5.0+` matches `+version.okhttp3=5.5.0+` in cui-test-mockwebserver-junit5-1.6.pom, JMH pinned 1.37, exec classpath uses `+includeScope runtime+` (jmh-core compile-scope → present; annprocess provided → correctly absent). `+benchmark+` profile flips `+skip.benchmark=false+`; `+smoke+` only retunes timings — matches CLAUDE.md; workflow uses `+-Pbenchmark+` after `+install -DskipTests+` (test classes still compiled, so the generators enforcer rule passes).
* Workflows: every action/reusable workflow pinned by 40-char SHA; top-level `+permissions: contents: read+` everywhere, job-level escalation only where needed; `+pr-agent.yml+` maps two secrets instead of `+secrets: inherit+`; dependabot covers maven + github-actions.
* benchmark-pages.py: file names come from `+Path.glob("*.json")+` (direct children only → no traversal via `+dst_dir / f.name+`), history-entry regex is `+fullmatch+`ed, no JSON is parsed from untrusted input.
* Generators classifier artifact is really built (maven-jar-plugin execution `+generators+`, core pom :131-154) and guarded by `+requireFilesExist+`/`+requireFilesSize+` at `+verify+`.
