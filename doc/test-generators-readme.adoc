== Maven Coordinates

[source,xml]
----
<dependency>
    <groupId>de.cuioss</groupId>
    <artifactId>cui-http</artifactId>
    <classifier>generators</classifier>
    <scope>test</scope>
</dependency>
----

[NOTE]
====
The classes in the `generators` classifier artifact depend on test-scope libraries
(`de.cuioss:cui-test-generator` and JUnit 5) that are **not** transitively propagated to
consumers. Add those dependencies explicitly (in `test` scope) alongside the classifier
artifact, otherwise the generator and attack-database classes will not compile in the
consuming project.
====

== Overview

Test artifact containing attack databases with curated real-world attack patterns and test data generators for security validation testing.

== Pattern Databases

The databases live in the
link:../cui-http-core/src/test/java/de/cuioss/http/security/database/[`de.cuioss.http.security.database`]
package; that source tree is the authoritative inventory of which databases exist (see
xref:adr/0004-Documentation_inventories_point_at_package-level_source_trees_not_per-class_enumerations.adoc[ADR-0004]).
Every database implements exactly one of two interfaces, and the interface tells you what a test
built on it asserts:

* **`AttackDatabase`** — curated attack patterns (CVE-based, standards-based and specialized sets)
  that must be *rejected*. Each entry is an `AttackTestCase` record carrying the attack string, the
  expected `UrlSecurityFailureType`, an attack description and the detection rationale.
* **`LegitimatePatternDatabase`** — legitimate inputs that must be *accepted*, guarding against
  false positives. Each entry is a `LegitimateTestCase` record carrying the legitimate pattern, a
  description of the use case and the acceptance rationale.

Each database exposes its entries through a nested JUnit 5 `ArgumentsProvider`, as the usage
examples below show.

== Test Generators

The test artifact includes generators organized by category (cookie, encoding, header, injection, url).

For complete generator architecture and categories, see xref:http-security/specification/testing.adoc[Testing Framework].

== Usage

=== With JUnit 5 Parameterized Tests

[source,java]
----
@ParameterizedTest
@ArgumentsSource(ApacheCVEAttackDatabase.ArgumentsProvider.class)
void shouldRejectAttacks(AttackTestCase testCase) {
    var exception = assertThrows(UrlSecurityException.class,
        () -> pipeline.validate(testCase.attackString()));

    assertEquals(testCase.expectedFailureType(), exception.getFailureType());
}
----

=== Direct Access to Test Cases

[source,java]
----
import static de.cuioss.http.security.database.ApacheCVEAttackDatabase.*;

@Test
void shouldDetectCVE202141773() {
    AttackTestCase testCase = CVE_2021_41773_PATH_TRAVERSAL_PASSWD;
    // Use testCase.attackString(), testCase.expectedFailureType(), etc.
}
----

=== Multiple Database Integration

[source,java]
----
static Stream<AttackTestCase> getAllTestCases() {
    return Stream.of(
        new ApacheCVEAttackDatabase(),
        new IISCVEAttackDatabase(),
        new OWASPTop10AttackDatabase()
    ).flatMap(db -> StreamSupport.stream(
        db.getAttackTestCases().spliterator(), false));
}
----
