== What is it?

Security-focused HTTP utilities library providing validation pipelines, SSL/TLS context management, and HTTP client handlers. The URL path and parameter pipelines include attack pattern detection.

== Components

=== HTTP Security Validation

xref:doc/security-readme.adoc[Security Validation Framework]:

* Validation pipelines for paths, parameters, headers
* Attack pattern detection for URL paths and parameters (path traversal, parameter injection, protocol violations); the header pipeline relies on character and length rules (plus allow/block lists for header names) instead
* Configuration via `SecurityConfigurationBuilder`

=== HTTP Client Handlers

xref:doc/client-handlers-readme.adoc[HTTP Client Handlers]:

* `HttpHandler` - Builder-based HTTP client with SSL defaults
* `SecureSSLContextProvider` - TLS 1.2+ SSL context
* `HttpStatusFamily` - RFC 7231 status classification
* Opt-in hostname-verification relaxation (`verifyHostname(false)`) - skips TLS identity matching only; certificate-chain validation is unaffected (xref:doc/client-handlers-readme.adoc[details])

=== Forwarded / Reverse-Proxy Header Resolution

xref:doc/forwarded-header-resolution.adoc[Forwarded Header Resolution]:

* Resolves `X-Forwarded-*`, RFC 7239 `Forwarded`, and NiFi `X-Proxy*` into one sanitized result
* Scheme / host / port / context-path / client-IP with configurable per-field precedence
* Secure-by-default trust model (allowlist, `trustAll`, trusted-proxy CIDR walk)
* Built-in sanitization via the security pipelines; transport-agnostic `Function<String, List<String>>` accessor exposing every instance of a repeated header

=== Security Testing

xref:doc/test-generators-readme.adoc[Test Generators]:

* Attack databases with CVE patterns and OWASP vectors
* Test data generators for security validation
* JUnit 5 integration with `ArgumentsProvider`

== Usage Example

[source,java]
----
// HTTP Client
HttpHandler handler = HttpHandler.builder()
    .uri("https://api.example.com/data")
    .connectionTimeoutSeconds(10)
    .build();

HttpClient client = handler.createHttpClient();
HttpRequest request = handler.requestBuilder()
    .GET()
    .build();
HttpResponse<String> response = client.send(request, HttpResponse.BodyHandlers.ofString());

// Security Validation
SecurityConfiguration config = SecurityConfiguration.builder()
    .maxPathLength(2048)
    .build();

URLPathValidationPipeline pipeline = new URLPathValidationPipeline(
    config, new SecurityEventCounter());

String validated = pipeline.validate("/api/users/123").orElseThrow();
----

== Build Commands

The primary build path is the plan-marshall build executor, which runs the Maven wrapper with a
given argument string and reports a structured result, for example:

[source,bash]
----
python3 .plan/execute-script.py plan-marshall:build-maven:maven run --command-args "verify -Ppre-commit"
----

The full set of executor commands is listed in the "Build Commands" section of `CLAUDE.md`. Each
one passes its `--command-args` string to the Maven wrapper, so the `./mvnw` equivalents below run
the same build:

[source,bash]
----
./mvnw compile                                  # Compile
./mvnw verify -Ppre-commit                      # Quality gate: auto-fixes license headers and applies the OpenRewrite recipes (MANDATORY; review and commit the diff)
./mvnw verify                                   # Full verify
./mvnw verify -Pcoverage                        # Coverage
./mvnw test -pl cui-http-core -am               # Tests (cui-http-core only)
./mvnw verify -Pbenchmark,smoke -pl cui-http-benchmarking -am   # Smoke benchmark run, not measurement-grade
----

One further command is wrapper-only — it has no executor counterpart in `CLAUDE.md` and is not
part of the one-to-one mapping above:

[source,bash]
----
./mvnw clean install                            # Build and install into the local repository
----

NOTE: AI coding agents use the executor commands from `CLAUDE.md` and do not hard-code
`./mvnw`/`mvn` when the executor is available. Contributors without plan-marshall have no
`.plan/execute-script.py` — the executor is generated per machine and is gitignored, so a fresh
clone does not contain it — and run the `./mvnw` equivalents above instead.
